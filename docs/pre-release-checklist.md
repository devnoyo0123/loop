# 릴리즈 전 실기기 확인 체크리스트 (v9/v10 — 촬영·파일 전환)

> 2026-10-30 · 빌드로 검증 안 되는 영역만 모았다. 전 테스트 199개 통과 상태에서 시작.
> **준비**: 기존 데이터가 있는 실기기 1대(업그레이드 경로) + 에뮬레이터 or 클린 기기 1대(신규 경로).

## A. 업그레이드 경로 — 기존 유저 데이터 보존 (최중요)

사진이 DB base64(v1.0.9)인 상태에서 새 빌드를 덮어 설치한다.

1. 업데이트 전: 사진 첨부 로그 2~3개 확인(스크린샷 대조용), 설정에서 **수동 내보내기로 .looplog 백업** 한 장 확보
2. 새 빌드 덮어쓰기 설치 → 첫 실행
3. 기존 로그 전부 그대로인지 — 텍스트·사진·루프 사슬·반복 칩
4. 사진이 파일 마이그레이션 후에도 정상 표시되는지(카드 썸네일 + 상세 전체)
5. 앱을 완전히 종료했다가 재실행 — 마이그레이션 재실행에도 이상 없는지(멱등)

## B. 촬영 흐름 (v9/v10 신규)

1. + 작성 → 📷 촬영 → 찍은 사진이 바로 첨부되는지 (셔터음은 기기 정책대로)
2. 🎬 동영상 촬영 → 1분 제한 동작 확인 → 민트 "동영상 첨부됨" 칩
3. 저장 → 로그 카드 상세 펼침 → "동영상 · 탭해서 재생" → 시스템 플레이어로 열리는지 **(FileProvider — 빌드로 검증 불가, 이것이 핵심)**
4. 사진 촬영 로그도 동일하게 상세·썸네일 정상
5. 로그 삭제 → 파일 고아 없는지(재가져오기 시 동영상·사진이 빠진 상태로 안 남는지 확인용으로 백업 후 비교)

## C. 백업·복원 (제외 결정 검증)

1. 설정 → 내보내기 → .looplog 확보 → **클린 기기/앱 데이터 삭제 후 가져오기** → 사진·동영상까지 복원되는지(무손실)
2. 자동 백업: 기기 설정에서 백업 → 목록에 앱 데이터가 25MB 이내로 유지되는지(사진·동영상 제외 효과)
3. (이해 확인) 자동 백업 복원만으로는 사진·동영상이 안 돌아온다 — 로그 텍스트는 살고 첨부는 숨김 처리. 의도된 트레이드오프(구글 포토 1차, 수동 내보내기 2차)

## D. 회귀 — 최근 변경 영역

1. 루프: 사슬 중간 로그에서 루프 걸기 → "사슬의 마지막 기록에서 이어짐" 행 → 걸면 끝에 붙는지 / "여기서부터" 분기
2. 반복 발화가 직전 발화에 체인으로 쌓이는지(루프 보기 = 첫 기록부터 한 줄)
3. 통계 시트 + 공유 카드 PNG 생성
4. 그때의 나 아침 알림(설정 토글) / "오늘 저녁" 칩 / 하루 마무리 시각 설정
5. 스타터 팩 — 클린 기기에서 빈 화면 3장 → 탭 → 자동 루프
6. 광고: 타임라인 네이티브 광고 정상 노출(테스트 단위)

## 데이터 안전 원칙 (참고)

- 마이그레이션은 **삭제가 아닌 복사+전환** — 파일이 디스크에 flush된 뒤에만 base64를 비운다. 어느 시점에 죽어도 base64가 남아 다음 실행이 이어간다(멱등).
- 마이그레이션 실패(디스크 부족 등)는 앱 시작을 막지 않는다 — 레거시 경로로 계속 읽히고 다음 실행에 재시도.
- 동영상 저장 실패 시에도 **로그 본문은 반드시 저장**된다(첨부만 누락).
- 유일한 영구 소실 시나리오: 자동 백업 복원(사진·동영상 제외) + 수동 내보내기를 안 한 경우. → 정기 내보내기 권장 문구가 설정에 이미 있다.
