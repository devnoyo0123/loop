# ADR-002 — MCP 엔드포인트를 맥(브리지)으로 옮기고 폰은 클라이언트로 접속

> 날짜: 2026-11-17 · 상태: **채택 — 실기기 검증 완료 (2026-11-17)** (ADR-001의 전송 방향 반전.
> ADR-001의 폰 내장 서버는 폴백으로 남길 예정이었으나, 같은 날 **스토어 출시 전 제거**로 최종 결정 —
> 스토어 버전에 구현된 적이 없어 사용자 영향 0, FGS `dataSync` 신고·유지비 부담 제거. §마이그레이션 참조)
> 선행: `docs/adr-001-local-mcp-server.md` · 상세 설계: `docs/mcp-bridge-design.md`
> **2026-11-18 부분 수정 → ADR-003**: "FGS 제거"로 생긴 화면 꺼짐·앱 전환 시 단선이 실사용에서
> 너무 불편해, 연결 중에만 도는 60분(유휴) `dataSync` FGS 세션을 되살렸다.
> `docs/adr-003-pc-link-fgs-session.md` 참조

## 배경

ADR-001(폰 내장 MCP 서버, 2026-11-12 채택)을 실기기·실맥에서 검증한 결과,
**검색 도구 자체는 동작하지만 "맥이 폰을 찾아 인증하는" 부트스트랩의 마찰이 상시 비용**으로
확인됐다 (2026-11-17, Galaxy Z Fold 6 + macOS 27.2 + Claude Code):

- 폰 IP·43자 토큰을 맥으로 옮길 마땅한 경로가 없다 — 폰↔맥 클립보드 미연동, 메신저 우회가
  현실적 해법이 됨. 사용자 원론: "Loop가 같은 Wi-Fi의 PC와 소통하는 창구가 필요하다"
- **macOS 로컬 네트워크 권한(TCC)**이 홈브류 node(Claude Code 런타임)의 LAN 접속을 차단한다.
  Apple 시스템 바이너리(curl/nc)는 통과하고 node만 `EHOSTUNREACH` — 공유기 주소로도 재현.
  설계 §11.3이 예측한 사례지만, 권한 팝업이 뜨지 않는 조합에서는 사용자가 자가 진단하기 어렵다
- DHCP로 폰 IP가 바뀔 때마다 재등록, 30분 자동 종료로 재토글 — 반복 노출

결론: 폰을 서버로 두는 한 "맥 → 폰" 방향의 발견·인증 문제는 개선(8자리 코드, mDNS)으로는
줄일 수 있어도 없앨 수 없다. **방향 자체를 뒤집으면 이 비용이 사라진다.**

## 결정

MCP 엔드포인트를 **맥의 브리지 서버**로 옮긴다. Claude Code는 localhost로 연결하고,
폰 앱은 클라이언트로 맥에 역방향 연결한다.

```
Claude Code ─ localhost ─ 맥 브리지 서버 ←── JSON-lines ── 폰 Loop 앱(데이터 원본)
             (영구 등록 1회)   (skill 플러그인이 기동)      (질의 → 응답만 흐름)
```

- **맥**: Claude Code 플러그인(`plugins/loop`)이 node 단일 파일 브리지를 번들.
  `plugin.json`의 `mcpServers`로 자동 등록 — 설치 즉시 `http://localhost:<port>/mcp`.
  사용자 맥 쪽 설정 절차 없음
- **폰**: 설정 → "PC 연결" 화면 — NSD(mDNS)로 맥 브리지 탐색 → 맥 터미널에 표시된
  **8자리 페어링 코드** 입력 → 연결. 코드·주소는 저장해 재접속은 자동
- **보안/프라이버시**: 기록은 여전히 폰에서 나가지 않고 질의→응답만 흐른다(로컬 퍼스트 유지).
  페어링 코드는 1회 상호 확인용이며 이후 재인증 없음. 폰에서 언제든 연결 해제·페어링 초기화
- **재사용**: 폰 `LoopDb.searchDetailed`/`chainLogs`/`logsOnDay`와 `mcp_tools.dart`의
  응답 생성, 맥 `mcp_protocol.dart`의 JSON-RPC 최소 구현을 그대로 이식

## 검토한 대안

| 대안 | 기각/보류 사유 |
|---|---|
| 폰 서버 유지 + mDNS·8자리 코드 개선 (ADR-001 후순위) | macOS TCC·IP 전달 문제가 **맥 쪽에 그대로 남음** — 오늘의 마찰을 줄일 뿐 없애지 못함 |
| 폰 서버 + 앱 내 웹 뷰(브라우저가 창구) | 브라우저로는 기록 열람만 되고 **Claude/AI 워크플로와 무관** — 목적 미충족 |
| 클라우드 중계 서버 | 로컬 퍼스트 위반 — ADR-001과 동일하게 기각 |
| KDE Connect식 상시 데몬(맥 상주) | 상시 운영·자동 시작 부담. 필요 시 접속(세션 중 기동)으로 충분 |

## 결과

**긍정**
- 맥 쪽 등록이 localhost 고정 1회 — DHCP·TCC·AP 격리와 무관, 오늘의 실패 계열 전부 원천 차단
- 부트스트랩 UX가 "폰에서 8자리 입력" 한 번으로 끝 — 43자 토큰 전달 문제 소멸
- 폰의 FGS·WifiLock·30분 자동 종료·배터리 부담 제거 (필요할 때만 붙고 끊음)
- 맥 셋업이 플러그인 설치로 끝남 — `claude mcp add` 수동 절차 자체가 사라짐

**트레이드오프**
- 맥에 node 런타임 필요 (플러그인 번들·의존성 없는 단일 파일로 완화)
- 폰↔맥 전용 프로토콜 신규 도입 (경량 JSON-lines, WebSocket 라이브러리 불필요)
- 기존 폰 서버 코드와 당분간 병행 — 문서·FAQ가 두 흐름을 다뤄야 함

**마이그레이션**
~~폰 내장 서버는 제거하지 않고 폴백/고급으로 유지한다~~ → **2026-11-17 변경: 완전히 제거했다.**
스토어 출시 버전에 구현된 적이 없어(스토어 배포판은 기능 자체 미포함) 사용자 영향이 0이고,
FGS `dataSync` 권한·Play Console 신고, 110개 l10n 키, 서비스 7파일의 유지비를 없애는 편이 크다.
Claude Desktop 등 stdio를 지원하는 다른 클라이언트는 `server.mjs`를 커맨드 서버로 직접
등록하면 동일하게 동작한다.
