## Loop 통합 (2026-08-31 결정)

"포크"라는 개발 용어는 비개발 사용자에게 안 맞고, 앱의 정체성은 Loop 하나.
이어쓰기(포크) + 한 번 알림 + 반복을 **Loop 한 기능으로 통합**했다.

- 개념: Loop = "이 로그로 다시 돌아오기".
  - 지금 돌아오기 = 이어쓰기 (기존 포크)
  - 나중에 돌아오기 = 알림 옵션 — 한 번 / 반복 (반복은 발화마다 이어쓰기 자동 생성)
- 로그 메뉴 7개 → 4개: `편집 / 시간 변경 / ↩ Loop / 삭제`
  (이어쓰기·알림 예약·반복 설정·반복 중지 항목 제거)
- 통합 Loop 시트 (`loop_sheet.dart`):
  - 거는 모드 (루프 없음): 미리보기 + [지금 이어쓰기] + "다시 알려줘"(한 번/반복) + [Loop 걸기]
  - 정보 모드 (루프 있음): 주기·다음 발화·N회째 + [원본으로 이동] + [지금 이어쓰기] + [루프 중지]
  - 반복 발화 로그의 칩("Loop N회째")과 원본 칩(주기 라벨) 탭 → 정보 모드.
    기존 "탭 = 곧바로 중지"에서 시트 경유로 변경 (실수 방지 + 상태 확인).
- 실시간 정산: `settleRepeats()`를 시작 시 1회만 돌리던 것 → 포그라운드 1분 타이머 +
  lifecycle resumed 에도 실행. 앱을 켜둔 채로도 다음 발화가 제자리에 생긴다.
- 용어 정리: UI에서 "포크" 표기 전부 제거 (이어쓰기/Loop로). 데이터 모델(parentId,
  repeatRuleId)은 그대로 — 표현층만 통합.

## 루프 보기 (2026-08-31 결정)

- **루프 사슬**: 최상위 원본 → 루프 → 루프의 루프 → … → 지금 로그.
  `parentId` 사슬을 따라간다 (DB `lineage(id)`).
- **진입** (사용자 결정: 탭 → 작은 시트):
  - 빈 루프 도착 로그(반복·단발 모두) 탭 → 시트 [↩ 루프 보기 / ✍ 작성하기]
  - 작성된 포크는 ⋯ 메뉴의 "루프 보기" (포크에만 표시)
- **화면**: 타임라인 대신 사슬만 시간순 표시. 맨 위에 라벤더 필
  ("루프 보기 · 되돌아가기") — 탭하면 전체 타임라인으로 복귀.
  날짜 이동과는 동시에 쓰지 않는다(진입 시 해제). 페이지 나눔 없음.

## 백그라운드 발화 신뢰성 (2026-08-31)

- **정확 알람 권한**: Android 14+ 기본 거부 → init에서 requestExactAlarmsPermission
  (허용됐으면 화면 안 열림). 예약 실패 시 inexact 폴백 — 몇 분 늦어도 울림.
- **알림 채널**: 매번 지우던 버그 수정 — 지우면 이미 예약된 알림이 발화 시점에
  채널이 없어 조용히 누락된다(특히 재예약 안 하는 단발). 이후엔 채널 id를
  올리는 방식으로만 설정 변경.
- **단발 루프 포크**: 발화 시각이 지나면 빈 포크를 발화 시각대에 생성
  (반복과 동일). 앱 시작·1분 타이머·복귀 때마다 정산.

## 망각곡선 루프 (2026-08-31 결정)

"루프가 1번 돌아왔으면 다음엔 더 긴 간격으로" — 에빙하우스 망각곡선을
한 번 알림의 기본 간격에 적용했다.

- **사다리**: 10분 → 1시간 → 1일 → 1주 → 1달 (5단계).
  기존 빠른 선택 칩에 1달을 추가하고 순서를 곡선과 맞췄다.
- **버튼과 적용값이 함께 변한다**: Loop 시트는 loop_count N에 따라
  N+1번째 간격 칩이 기본 선택되고, 큰 시각 표시(실제 걸리는 값)도
  그 간격에서 시작한다. 다른 칩/직접 선택은 언제나 가능.
- **루프 카운트**: 단발 루프 발화마다 원본 +1 (v6 `loop_count` 컬럼).
  발화로 생긴 포크는 카운트를 이어받아 태어나므로 포크에서 다시 걸어도
  곡선이 이어진다. 발화 전 "지금 이어쓰기"로 소비해도 +1.
- **힌트 문구**: 시트 상단에 "망각곡선 {n}번째 복습 · 추천 {간격}" 표시.
- **끝에 도달하면**: 1달을 유지한다 (반복 규칙 전환은 제안하지 않음).
- **크래시 수정**: "매일" 프리셋에서 timeOfDay에 시간만 저장해
  `RangeError (length)`가 나던 버그 — "HH:mm" 완전형으로 저장하고
  파싱은 레거시 값("09")도 방어.

## 다가오는 루프 미리보기 · 평일 반복 (2026-10-17 결정)

- **미리보기 시트**: AppBar `↑` 아이콘 → 오늘부터 7일 창의 루프를 한 장에.
  단발 루프는 창 안 전부, 매일/평일 반복은 매 발화가 한 줄, 분/시간 반복은
  다음 발화만(7일치를 늘어놓으면 수백 줄). 행 = 시각+요일 · 원본 내용 1줄 ·
  규칙 라벨. 탭하면 그 원본 로그가 있는 날로 타임라인 이동(검색 점프 패턴).
- **빈 루프 포크 미리보기**: "비어 있음" 대신 원본(부모) 내용 앞 10자 + ….
  루프를 누르기 전에 무엇에 대한 루프인지 보인다. 부모를 모르면 기존 힌트.
- **평일 반복**: 반복 프리셋에 "평일" 추가 — 토·일·한국 공휴일(관공서 기준
  날짜표, 2026~2028)을 건너뛰고 발화 시각을 유지한다. 라벨 "평일 09:00".

## 기록 흐름 통계 (2026-10-25 결정)

- **진입**: AppBar 인사이트 아이콘 → 바텀시트. 스토어 공개 직전, "기록이
  쌓이는 이유"를 보여주는 화면 (기획 전체·로드맵: docs/growth-ideas.md).
- **내용**: 핵심 숫자 4개(쓴 기록·기록한 날·지금 연속·최장 연속) · 하이라이트
  라인 "생각이 N번 다시 돌아왔어요"(단발 복습 + 반복 발화 합산) · 최근 15주
  히트맵(월요일 시작, 라벤더 4단계 농도, 오늘 칸 민트 테두리, 미래 칸은
  투명) · 가장 많이 이어진 사슬 TOP 3(탭 = 루프 보기 진입 — 미리보기 시트와
  같은 패턴). 기록이 없으면 안내 문구만.
- **집계 원칙**: 날짜 버킷은 전부 기기 시간대 — SQL 날짜 함수(UTC) 대신
  epoch 밀리초를 `lib/utils/loop_stats.dart`(순수 로직)에서 계산.
  "쓴 기록"은 내용이 있는 로그만(반복 빈 포크 제외). 스트릭은 오늘이 비어
  있으면 어제까지 센다(GitHub 잔디 관례). 연속 판정은 24시간 차가 아니라
  달력상 전날 비교 — DST 시간대에서도 안전.
- **돌아온 횟수 산출**: 체인(COALESCE(root_id, id))별 loop_count 최댓값의
  합 + 반복 규칙 fire_count 합. 포크가 카운트를 이어받아 태어나는 구조라
  체인별 최댓값이 그 사슬의 복습 횟수다.

## 그때의 나 · 공유 카드 · 첫 루프 스타터 팩 (2026-10-25 결정)

성장 기획 2차 인큐베이팅 (전체: docs/growth-ideas.md "인큐베이팅 v2").

- **그때의 나**: 오늘부터 8일 치 아침 9시 알림을 미리 예약 — 각 날짜의
  1주/1개월/1년 전 기록 중 가장 먼 재회(1년→1개월→1주)를 골라 "미리보기 ·
  1년 전 오늘"로. 그날의 과거는 예약 시점에 이미 과거라 미리 계산해도
  정확하다. 탭 = 그 기록의 날로 이동(기존 알림 탭 패턴). 채널 분리
  ('onthisday', 확인 액션 없음), 설정 토글(기본 ON), 하루 한 번만 재예약.
  월·년 날짜는 말일 클램프(3/31→2/28, 2/29→2/28).
- **공유 카드**: 통계 시트 공유 버튼 → 540×675 카드를 화면 밖 오버레이에
  그려 1080×1350 PNG 캡처 → 시스템 공유 시트(share_plus). 카드 구성 =
  브랜드 · "생각이 N번 다시 돌아왔어요" · 숫자 4개 · 히트맵 · 태그라인.
  히트맵 격자는 `widgets/heatmap.dart`로 추출해 시트와 공유.
- **첫 루프 스타터**: 텅 빈 최신 타임라인에 3장 — 10분 루프 / 매일 밤 9시 /
  일주일 루프. 탭 → 작성 시트(상단 민트 배너 "↩ 10분 뒤 다시 돌아와요") →
  저장하면 루프/반복이 자동으로 걸린다. 사용자 직접 예약(⏰)이 우선.
  날짜 이동 중 빈 화면은 기존 안내 문구 유지.

## 루프 부착점 — 사슬의 끝에서 (v8, 2026-10-30 결정)

문제: 루프는 "현재 보인 로그"에 달렸다. 망각곡선 흐름(도착 포크에서 이어 걸기)은
문제없지만, 사슬 중간의 옛 로그에서 걸면 그 시점으로 분기가 나고 루프 보기가
조각나며 곡선 회차도 옛 값에서 재시작됐다. 반복은 원본 고정 방사형이라 매일 밤
기록이 한 사슬로 안 보였다. (사용자 제기)

- **규칙 하나로 통일**: "루프는 항상 사슬이 지금 끝나는 지점에서 이어진다.
  다른 지점을 고르면 그때부터 분기." 단발·반복 모두.
- **Loop 시트**: 보인 로그가 사슬 중간일 때만 "이어짐 위치" 행 표시 —
  "↩ 사슬의 마지막 기록에서 이어짐" + 끝 미리보기 + [여기서부터] 토글.
  끝이 곧 보인 로그면 행 자체가 없다(일상 흐름 UI 변화 없음).
- **부착 결정**: 타임라인이 `latestLeafOf(logId)`(서브트리 최신, materialized
  path 전방 일치)로 끝을 찾아 전달. 망각곡선 칩·적용값도 부착 대상의 회차로.
- **반복 발화**: `settleRepeats`가 직전 발화(첫 발화면 원본 줄기의 최신)에 체인.
  캐치업 순서 = 사슬 순서. 원본·하위가 전부 삭제된 규칙은 고아 발화를 만들지
  않도록 조용히 건너뛴다. 칩·발화 수는 원본(부착 대상) 기준 유지.

## 하루 마무리 시각 (2026-10-30 결정)

문제: 단발 곡선이 10분 → 1시간 → (절벽) → 내일이라, 오후에 적으면
"지금 당장도 아니고 내일도 아닌" 간극이 생긴다. "오늘 저녁"은 기준이
모호하다는 사용자 지적 → 일몰(계절·위치 변동)·취침 시각(OS 미제공)·학습
(콜드스타트 실패)을 검토하고 **고정 시각 하나**로 풀기로.

- **하루 마무리 시각**: 기본 21:00, 설정 → "하루 마무리 시각"(시계 피커)
  에서 변경. settings 테이블 `day_end` ("HH:mm", 깨진 값은 기본 폴백).
- **"오늘 저녁" 칩**: Loop 시트·작성 ⏰ 피커의 칩 행에 추가 — 곡선 간격
  칩들과 나란히. 간격이 아니라 절대 시각을 찍는다(지났으면 내일 저녁).
  곡선의 5단계는 건드리지 않는 편의 칩.
- **한 기준의 재사용**: 스타터 "매일 밤 한 줄"(하드코딩 21:00 → 설정값),
  추후 그때의 나의 저녁 짝도 이 값으로. `dayEndStarter(hhmm)` /
  `nextDayEnd(hhmm, now)` / `SettingsSheet.dayEndOf(db)`.

## 루프 발견성 — 본문 상세에 [Loop 걸기] (2026-10-30 결정)

문제: 스타터는 텅 빈 화면에만 떠서, 스타터를 안 타고 쓰기 시작한 사용자는
루프가 ⋯ 메뉴에 숨어 있는 줄 모른다. (사용자 지적 — "루프 어떻게 거는지
모를 거 아니냐")

- **해결**: 본문 탭으로 펼쳐지는 상세 영역 맨 아래에 [↩ Loop 걸기] 버튼을
  상시 노출. ⋯ 메뉴의 루프와 같은 `LogMenuAction.loop` — 걸면 v8 규칙
  (사슬의 끝에서 이어짐)이 그대로 적용된다.
- 원칙: 타임라인 접힌 카드는 순수하게 (버튼 없음) — 펼쳤을 때만 행동
  선택지가 나타난다. 빈 루프 도착 로그는 탭 자체가 액션 시트라 버튼 없음.
- 남은 발견 경로: 작성 시트 ⏰ 버튼 / ⋯ 메뉴 / 본문 상세 버튼 / 스타터.

## 사진 촬영 첨부 · 무음 기능 기각 (2026-10-30 결정)

- **무음 촬영 기각 경위**: 사용자 제안 → 검토. 한국·일본은 셔터음 규제
  (2004~, 기기 수준 강제) 지역이고, 공개 API(enableShutterSound false)는
  이 지역 기기에서 OS가 무시한다. 전용 무음앱이 남아 있는 건 Play가 전면

  문제 될 케이스는 우회 핵(영상 프레임 추출 등)·한국 대상 무음 마케팅·
  은밀한 UX 세 가지 — 전부 배제하기로 함.
- **사진 촬영 첨부 (구현)**: 작성 시트 첨부 행에 촬영 버튼 추가 —
  image_picker가 시스템 카메라 인텐트를 대행하므로 카메라 권한·네이티브
  코드가 필요 없고, 셔터음은 기기 카메라 앱 정책을 그대로 따른다(앱이
  소리에 관여하지 않는 게 최선의 법적 위치). 찍은 한 장은 갤러리 첨부와
  같은 압축 파이프라인(1080px q80)으로.
- **비디오 첨부**: 후보로 스코프만 확정 (growth-ideas.md) — 파일 기반
  저장(로그 DB 아님), 자동 백업 제외, 내보내기 형식 영향 등 결정 포인트가
  있어 별도 인큐베이팅으로.

## 동영상 첨부 (v9, 2026-10-30 결정)

- **촬영**: 작성 시트 🎬 버튼 — 시스템 카메라 동영상 모드(사진과 같은
  인텐트 방식), 최대 1분. 첨부되면 ⏰ 자리 옆에 민트 칩 "동영상 첨부됨".
- **저장**: 파일은 `videos/<id>.mp4`(VideoStore), DB `log_videos`엔 파일명·
  크기만 — 이미지 base64 인라인과 달리 로그 DB를 보호한다. 로그당 1개.
- **재생**: 상세 펼침의 "동영상 · 탭해서 재생" 행 → FileProvider로 시스템
  플레이어 위임. 내장 플레이어는 넣지 않았다(가벼움 우선).
- **무손실**: 내보내기가 video 라인으로 base64 인라인, 가져오기가 파일로
  복원 — .looplog 무손실 원칙 유지. 파일이 없으면(메타만 백업 등) 상세
  행을 숨겨 조용히 처리.
- **백업**: videos/ 는 자동 백업·D2D 제외(25MB 한도 보호) — 수동 내보내기가
  동영상의 안전망. 설정 화면 문구는 기존 유지.

## 이미지 파일 전환 (v10, 2026-10-30 결정)

- **사용자 결정 배경**: 사진의 DB base64 저장은 로그 DB를 불린다 —
  파일 기반(비디오 v9 패턴)으로 전환. "갤러리 원본 직접 참조"는 검토했으나
  기각: 갤러리 정리 시 로그 이미지 소멸, content URI 권한 만료, .looplog
  무손실 붕괴. **소유한 복사본**이 저널의 정답.
- **저장**: `images/<imageId>.jpg`(ImageStore) + `log_images.file_name`.
  이중 경로 — 파일 우선, 레거시 base64 폴백(스토어 없는 DB·구백업 호환).
- **마이그레이션**: `migrateLegacyImages()` — 레거시 행을 파일로 옮기고
  base64를 NULL로. **멱등**(파일 쓰기↔UPDATE 사이 크래시여도 다음 실행이
  이어감). 앱 시작 때마다 호출, 할 일 없으면 즉시 통과.
- **백업**: images/ 도 자동 백업·D2D 제외(videos/와 동일) — 구글 포토
  백업이 사진의 1차 안전망이라는 사용자 판단. 없는 장은 카드 표시기·상세
  행에서 **조용히 숨김**(보이지 않는 사진의 "N장" 칩은 거짓말).
- **삭제**: 로그 삭제 시 이미지·동영상 파일 본문도 함께 정리(고아 방지).

## 사진 크기·동영상 전용 저장·썸네일 (v10.2, 2026-10-30 결정)

사용자 실기기 피드백 3건:
- **사진 크기**: 접힌 카드의 이미지 전용 높이 176→120(일반 카드와 비슷하게),
  펼친 이미지에 300px 상한 + contain(세로 사진이 화면을 통째로 차지하지 않게).
- **동영상만 찍어도 저장**: 작성 저장 조건에 동영상 포함 — 내용 강제하지 않음.
- **동영상 썸네일(유튜브 스타일)**: 저장 시점에 대표 프레임(첫 프레임, 너비
  640 JPEG)을 추출해 `<id>.jpg`로 보관하고, 카드(내용 없는 동영상 로그)와
  상세에 재생 오버레이 프리뷰로 표시. 탭 = 시스템 플레이어 재생. 썸네일이
  없으면 기존 아이콘 행 폴백. 추출은 video_thumbnail 패키지 대신
  **네이티브 MediaMetadataRetriever** 직접 구현 — 패키지의 Gradle 호환
  문제(구 AGP 충돌)를 우회.
